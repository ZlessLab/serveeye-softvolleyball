# ソフトバレー得点管理アプリ（ServeEye）

4人制ソフトバレーボール用 PWA スコア管理アプリ。

## 起動方法

```
node server.js
```

ブラウザで `http://localhost:8080` を開く。

## 購入前の操作体験と購入導線（2026-10-21）

- `/`（LP）→ `/demo.html`（固定サンプル5段階）→ 明示的な購入操作 → 既存Stripe Checkout → 購入完了案内 → メールのコードで既存アプリを認証。
- 体験は無料のスコア管理アプリではありません。チーム名、得点、サーブ順、結果は固定。任意入力、実時間タイマー、履歴保存、コピー、ライセンス情報へのアクセスはありません。リロードしても同じ説明用サンプルだけを再生します。
- 有料アプリの得点処理・ライセンス認証・価格設定・決済バックエンドは変更していません。現在の販売価格/受付状態は既存 `/api/campaign/status` から取得し、取得失敗時に架空の価格で決済へ進めません。決済開始はユーザー操作時のみです。
- `purchase-ui.js` をLP・体験・アプリで共有。受付終了、通信失敗、価格未取得時の案内、二重クリック防止、Stripe以外へのリダイレクト拒否を実装。
- LPの端末解除FAQはサポートへの案内に訂正。未実装の「72時間後自動再認証」は宣伝文から削除。既存認証方式の強化は今回の対象外です。
- `mobile/` のiOS準備作業には変更を加えていません。

### 検証

`npm test` で既存8件＋新規12件（合計20件）のNodeテストを実行。固定状態遷移、サーブ権移動時のみ回転、取消、終端、価格同期、連打、販売終了、通信失敗、不正な遷移先、体験の状態分離を確認します。テストのfetchはモックで、実際のCheckoutセッション作成・決済・メール送信は行いません。

既存 `node server.js` は `/` を有料アプリに向ける開発用サーバーです。LPは `/index.html`、体験は `/demo.html` を開いてください。ローカル静的サーバーでは `/api/*` が動かないため、購入欄は「販売情報を確認できません」と表示されるのが正常です。本番相当の販売欄のUI確認ではAPIモックか適切な開発環境を用い、無断の実決済を行わないでください。

ブラウザ確認項目: 375px幅で横はみ出しなし、5段階の操作と再生、連打、購入済みリンク、キーボードフォーカス、販売情報失敗/再試行、既存の有料アプリ認証画面を維持。バックエンドの購入後配信・実認証は今回のテスト対象外です。
