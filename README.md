# ServeEye 運用・開発ガイド

4人制ソフトバレーボール用の有料PWAです。このREADMEを現行運用の入口とします。作成に使うAIツールが変わっても、稼働中の決済・認証・配信基盤は別途移行しない限り必要です。

## 正本と作業範囲

- GitHub: https://github.com/ZlessLab/serveeye-softvolleyball 。本番の正本は実際に配信されたコミットで確認します。mainや作業フォルダが自動的に本番最新版とは限りません。
- Web: index.html（紹介）、demo.html（固定サンプル）、soft-volleyball-score.html（有料アプリ）、purchase-complete.html、legal/。
- API: api/、共有処理: lib/ と config/。Vercel配信設定: vercel.json / .vercelignore。
- DB定義の参照先: supabase/schema.sql。ただし下記のRPC定義が不足しており、これだけで本番を完全再構築できる状態ではありません。
- 環境変数の名前と用途: .env.example。実際の値は対象環境の管理画面で管理し、リポジトリや資料に貼り付けません。
- mobile/ios/ は別のiOS準備作業です。Webとの差分や生成ファイルを古い残骸と判断して削除しないでください。申請可能な完成品ではありません。
- 過去の変更記録は docs/archive/maintenance-history.md。FUNNEL-QA.md / FUNNEL-RESEARCH.md は購入導線変更の検証・背景資料です。

## 開発・テスト

依存関係: npm install
テスト: npm test
静的画面の確認: node server.js

http://localhost:8080/ は有料アプリ、/index.html はLP、/demo.html は体験ページです。このサーバーは開発用で、APIや環境変数の自動読込には対応していません。APIが必要な動作はモックまたは適切な開発環境で確認します。単に.envを作ってもAPIサーバーは起動しません。

本番依存は @supabase/supabase-js、stripe、resend。npm test はモックを使い、実際の決済・メール送信を行いません。静的な配信除外テストも含みますが、Vercel上のビルド・配信確認の代わりにはなりません。

## 維持する設定・データ

- Vercel: 配信ドメイン、対象ブランチ、Preview/Productionごとの環境変数。似た名前のプロジェクトも用途確認前に削除しません。
- Stripe: Checkout、Webhook、販売中および既存購入に関係する商品・価格。config/plans.jsの将来プランや価格ID補正は実運用確認まで保持します。
- Supabase: 購入者、購入、ライセンス、端末、販売数、監査記録。コードから参照が少ないテーブルにも既存データや管理用途があり得ます。
- Resend: 購入後の認証コード送信。送信元ドメイン設定を保持します。
- PWA: manifest.json、sw.js、ルートアイコン、icons-generated/。古いURL /soft-volleyball-score.html と /serveeye の互換性を維持します。

## 復旧手順の未確認事項

api/webhook.js は increment_campaign_sale RPC を呼びますが、supabase/schema.sql にその関数定義はありません。本番に存在しないという意味ではありません。管理権限のある担当者が実DBの関数定義・権限・依存トリガーを読み取り確認し、レビューしたマイグレーションとして正本へ追加するまでは、新規DBへの切替や既存DB削除をしないでください。想像したSQLを本番で実行しないでください。

LICENSE_CODE_SECRET は購入後コード発行に必要です。既存環境の値は継続使用し、この整理のために再生成・変更しません。Stripeのテスト/本番のキーやWebhook、Supabase、Resendが同じ用途の環境を向いていることを確認します。

本番とテストのVercelプロジェクトの役割・ドメイン・環境変数の対応は管理画面での確認待ちです。権限不足を別経路で回避せず、確認できるまで削除・統合・本番反映を保留します。

## 安全な整理と復旧

今回の整理は未使用依存 nanoid と重複SQLファイルの除去、手順の一本化、管理用ファイルの配信除外です。決済・認証・価格・DB・iOS・アイコンの実装を変更しません。getPlanBySlug も公開済みのexportなので、外部利用の不明点を増やさないため保持します。

整理前の復旧用バックアップを1つ保存し、GitHubの既存履歴も保持します。復元時はバックアップを別ディレクトリへ展開し、必要な差分だけ戻してnpm installとnpm testを実行してください。バックアップにはnode_modules、.git、実際の秘密値を含めません。環境変数は既存の安全な管理先から復旧します。バックアップの展開や古いコードへの本番切替は、自動で実施しないでください。

公開前に対象コミット、テスト結果、配信除外、必要なAPI・アイコン・法定ページの保持をレビューします。このローカル整理だけでは公開・本番反映済みではありません。

## 購入前の操作体験と購入導線（2026-10-21）

- `/`（LP）→ `/demo.html`（固定サンプル5段階）→ 明示的な購入操作 → 既存Stripe Checkout → 購入完了案内 → メールのコードで既存アプリを認証。
- 体験は無料のスコア管理アプリではありません。チーム名、得点、サーブ順、結果は固定。任意入力、実時間タイマー、履歴保存、コピー、ライセンス情報へのアクセスはありません。リロードしても同じ説明用サンプルだけを再生します。
- 有料アプリの得点処理・ライセンス認証・価格設定・決済バックエンドは変更していません。現在の販売価格/受付状態は既存 `/api/campaign/status` から取得し、取得失敗時に架空の価格で決済へ進めません。決済開始はユーザー操作時のみです。
- `purchase-ui.js` をLP・体験・アプリで共有。受付終了、通信失敗、価格未取得時の案内、二重クリック防止、Stripe以外へのリダイレクト拒否を実装。
- LPの端末解除FAQはサポートへの案内に訂正。未実装の「72時間後自動再認証」は宣伝文から削除。既存認証方式の強化は今回の対象外です。
- `mobile/` のiOS準備作業には変更を加えていません。

### 検証

`npm test` で既存8件＋購入導線12件＋管理構成4件（合計24件）のNodeテストを実行。固定状態遷移、サーブ権移動時のみ回転、取消、終端、価格同期、連打、販売終了、通信失敗、不正な遷移先、体験の状態分離を確認します。テストのfetchはモックで、実際のCheckoutセッション作成・決済・メール送信は行いません。

既存 `node server.js` は `/` を有料アプリに向ける開発用サーバーです。LPは `/index.html`、体験は `/demo.html` を開いてください。ローカル静的サーバーでは `/api/*` が動かないため、購入欄は「販売情報を確認できません」と表示されるのが正常です。本番相当の販売欄のUI確認ではAPIモックか適切な開発環境を用い、無断の実決済を行わないでください。

ブラウザ確認項目: 375px幅で横はみ出しなし、5段階の操作と再生、連打、購入済みリンク、キーボードフォーカス、販売情報失敗/再試行、既存の有料アプリ認証画面を維持。バックエンドの購入後配信・実認証は今回のテスト対象外です。
